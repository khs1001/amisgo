## 追加：同名层级回退 + include 函数 + 布局模式

- 同名层级回退（方案 A）：查找链 = 完整路径逐级去前导目录段（user/list → list），每个候选先查完所有来源（本地→fs 注册顺序）再回退层级；层级优先于来源
- include 内置函数（参考 GoFrame gview include 嵌入方式，用户明确参考该文档选定）：`{{include "sign"}}`（编译期改写自动补 dot）与 `{{include "sign" 数据}}`；结果对象注入；goroutine 级渲染状态（goid via runtime.Stack）继承 cxt 与深度；MaxIncludeDepth=64 防循环引用；布局模式 = include 组合约定（布局页 `{{include .mainTpl .}}` 动态主内容），无专门 layout 函数/字段
- 关键实现点：特征码在 JSON 字符串值内，内部引号是 `\"`，模板解析前需 unescapeFeatureCodes 还原（`\"`→`"`、`\\`→`\`）——这是踩过的坑
- 特征码必须"整个字符串值以 {{ 开头"，`"HEADER {{.x}}"` 不是特征码（测试用例曾因此写错）
- 后续修订（用户指示）：特征码内部字符串参数改用**反引号 raw string**（`{{include `sign`}}`），JSON 中无需转义；unescapeFeatureCodes 已整体移除，测试/README 均改为反引号写法
- 再修订（用户指示）：**移除 wrapActions 整套 AST 改写**，改为规范约定——引擎只注册内置函数 `json`（JSON 编码，缺失/nil→null）与 `include`（1~2 参，单参= nil data）；页面作者按规范写 `{{.x | json}}`、`{{include `sign` . | json}}`；include 结果也是值注入，同样要 `| json`（测试踩过：漏写导致 fmt 打印 map 破坏 JSON）。缓存基准渲染对含 include 的页面自动退化（nil data 下 include 报错被容忍）
